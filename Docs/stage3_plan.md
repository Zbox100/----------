# 阶段 3 方案拆步（B1 / B4 / B2+B3 / IIC 全量合并）

本文件把阶段 3 的重构拆成"可独立验证的步"，给出先后、依赖与验收点（可逐项打勾）。
配套：`observability_log.md`（实测证据留档）、`notes_rtos.md`（问题清单）。

## 0. 当前事实（判断的依据）

| 项 | 现状 | 影响 |
|---|---|---|
| 调度配置 | `configUSE_PREEMPTION=0`、`configUSE_TIME_SLICING=1`、tick 1000Hz | **抢占关闭 ⇒ 时间片调度实际失效**：节拍中断不触发切换，"同优先级轮流"不会自动发生；任务必须自己阻塞才让出 CPU |
| 任务优先级 | 业务任务均为 4；`Usart_Rx_f`=3 | 同优先级靠"阻塞让出"协作 |
| 长非阻塞段（疑似饿死源） | `blood_Loop()` 的 FFT；DHT11 的 `Delay_fnms(18)` 忙等 + 位读取超时；`Key_GetNum()` 的按键自旋 | 谁不阻塞，别人就干等 |
| 4 个 Show 任务 | 抢**同一条** `KeyExitHandler`（长度 1） | "4 抢 1，只有一个能收到"——B2 要解决的实证问题 |
| 软 IIC | 3 套重复实现：ADXL(PA4/PA5)、OLED(PB8/PB9)、MAX30102(PA11/PA12) | IIC 全量合并的对象 |
| 中断优先级 | 调 `FromISR` 的中断抢占优先级已 ≥5 | 抢占开启的前置条件已满足 |
| `configASSERT` | 处于注释状态 | B1 实测需临时打开 |

## 1. B1 调度模式评估（论证 + 实测）

结论：**值得改，但启用排在 B2 / IIC 合并之后。**

- **收益**：长非阻塞段会被节拍切走，不再独占 CPU；`S`/`G` 类"任务循环间隔峰值"指标应显著收敛。
- **代价/风险**：
  1. 同优先级任务可被随时打断 ⇒ 所有未保护的共享变量变成竞态。`global_var`/`KeyExit_R` 已有临界区，但"4 个 Show 任务共用一条 len=1 队列"这类**隐式依赖"同优先级不打断"**的设计会暴露。
  2. `FromISR` 中断抢占优先级必须 ≥5（已满足）。
  3. 软 IIC 若将来出现两任务共享一条总线，会互相破坏（当前三路各自独立，暂无此问题）。
- **为何排在后面**：先把隐式依赖清干净（B2 的广播、IIC 的互斥边界），再开抢占，竞态风险最小。

### 实测方案（复用现有 `S`/`G` 探针）

- [ ] 做两个构建（抢占 0 / 1），各走一轮"四页都切 + 计步 + 血氧"
- [ ] 对比 ① `S`/`G` 峰值是否收敛；② 打开 `configASSERT` 是否触发；③ 现象是否复现
- [ ] 产出"抢占后需加保护的共享变量清单"，逐条确认已加临界区

## 2. 三块的先后与验收点

### 步 1 ｜ B4 事件组机制掌握（前置，10-16~10-17）

- 为何必须先：B2 要用；R16 复述不过不进 3B。
- [ ] 验收：**不看资料**口述通过，且讲清三个要点——事件组是**位广播**、**不计数**、`xEventGroupClearBits` 会整体重置
- [ ] 验收：能区分事件组与队列/信号量的适用边界

### 步 2 ｜ B2 事件组广播（+ B3 选型）（10-18）

- 要解决的实证问题：4 个 Show 任务抢同一条长度 1 的 `KeyExitHandler`，"只有一个能收到"。
- 交付：把"退出页面"从"发队列值"改为"**置事件位**"，4 个 Show 任务各自 `xEventGroupWaitBits`。
- [ ] 验收①：任一面进入 → 按退出 → **4 个 Show 任务都观察到该位**（加一次性计数可见）
- [ ] 验收②：退出后位被清除，连按两次不重复触发
- [ ] 验收③：改前"只有一个任务收到、其余卡住不刷新"的现象消失
- [ ] 验收④（B3）：能讲清**为什么用事件组而不是 5 个信号量**——广播语义、单对象不占堆、ISR 安全，以及"此处不需要计数"这一前提

### 步 3 ｜ IIC 全量合并（放最后）

- 目标：3 套软 IIC 合并为一份**引脚参数化**的驱动，删掉各驱动内联的位带时序；各设备驱动只留寄存器地址与数据换算。
- 为何最后：纯重构、与调度/事件组正交；先做会把"抢占竞态"与"驱动重构"两个变量混在一起，出问题难定位。
- [ ] 验收①（逐一单验）：ADXL 静止 `mag≈1000`；OLED 四页都能画；MAX30102 `PART_ID=0x15` 且能读数
- [ ] 验收②（三路同验）：四页切一遍 + 计步 + 血氧同时跑，无互相干扰
- [ ] 验收③（删重复的证据）：三份 Start/Stop/SendByte/RecvByte 只剩一份（行数 / `.map` 对比）
- [ ] 验收④（行为回归）：计步阈值命中情况、血氧数值与合并前同姿势一致
- [ ] 顺带产出：**总线互斥边界**说明（三路独立总线 ⇒ 无需互斥；将来共享再引入）——B1 的前置材料
